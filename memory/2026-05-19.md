# Memory Log - 2026-05-19

## Issue Diagnosed
- **User Request:** When the user types `"xuất phát từ hà nội, 3 ngày 2 đêm, budget 10tr"` (where the previous destination was "Sapa"), the form incorrectly fills both "Khởi hành từ" and "Đến điểm đến" as "Hà Nội" (overwriting Sapa).
- **Root Cause:** 
  1. The regex entity extractor (`entity_extractor.py`) blindly matched `"hà nội"` in the destination keyword list because `"hà nội"` was present in the user's prompt (inside `"xuất phát từ hà nội"`). This caused `destination: "Hà Nội"` and `origin: "Hà Nội"` to both be extracted.
  2. Because `"Hà Nội"` is a valid destination in the local JSON dataset, `parse_pipeline.py` bypassed the LLM repair logic, so the incorrect regex match was never corrected.
  3. In the React frontend (`PlanTrip.tsx`), the form would blindly overwrite the existing destination with the AI-parsed destination even if the parsed destination was merely a suggested city by the LLM (which happens when the prompt specifies no destination).

## Solution Implemented
1. **Python AI Service (`entity_extractor.py`):**
   - Added `"sapa"` to the quick destination keyword list.
   - Filtered out the matched starting point phrase (origin) from the query text before matching for the destination city. This successfully prevents a starting city (like Hà Nội in `"xuất phát từ Hà Nội"`) from being falsely parsed as the destination.
2. **Typescript API Interface (`api.ts`):**
   - Added the `destinationIsSuggested` optional boolean field to the `ParseTripResult` interface.
3. **React Frontend (`PlanTrip.tsx`):**
   - Modified `handleAiParse` to check if `result.destination` is suggested.
   - If the user already has a destination manually filled out in the form (e.g. `"Sapa"`) and the AI's parsed destination is just a suggestion (e.g. because no destination was provided in the prompt), the frontend preserves the existing destination instead of overwriting it.

## Testing & Verification
- Tested the extractor manually and verified it returns `destination: null` and `origin: "Hà Nội"` for the target prompt.
- Tested the API endpoint and verified that the hybrid AI pipeline fallback works flawlessly: the LLM suggests `"Đà Nẵng"` but correctly marks it with `"destination_is_suggested": true`, allowing the frontend to preserve `"Sapa"`.
